# P04备份恢复实施计划

设计依据：`docs/superpowers/specs/2026-09-12-backup-recovery-design.md`。用户已授权持续实施、独立验收及CI通过后自动合并，按以下行为逐条RED→GREEN推进。

## 1. 确认真实备份源

- 首条失败测试：缺少任意业务库的源必须拒绝，不能像旧脚本那样只导出magictools。
- 实现Docker源检查，验证固定PG镜像/平台、PG16主库、系统标识、八库清单、单PGDATA布局、复制权限及可用资源；不读取密码到公开输出。
- 继续验证外部表空间、外置配置、错误容器、数据库不可达与失败命令不能被当成可备份。
- 用新建隔离pgvector实例验证实际检查，保持原5432与共享实例不变。

## 2. 打通整集群备份与恢复

- 先写一条八库标记和角色可恢复的真实场景，验证缺少备份入口/产物时确实失败。
- 通过临时工具容器、私有PGPASSFILE与专用卷运行pg_basebackup tar+流式WAL，记录源身份、时间和WAL范围。
- 对新卷按PGDATA/pg_wal布局解包，完整pg_verifybackup通过后启动全新目标；已有卷/网络/容器拒绝覆盖。
- 逐项补角色实际登录和权限允许/拒绝、pgvector、八库数据及备份后marker边界验证。

## 3. 保护备份文件与状态

- 用错误密钥、损坏文件、清单改动、遗漏WAL和中断生产者建立失败测试。
- 每文件独立nonce的AES-256-GCM，文件AAD固定身份；清单整体HMAC经HKDF分离认证key，先认证再信任镜像/路径。
- 文件容量上限、流错误、空间不足、原子完成清单、失败回执、锁及清理结果纳入结果判断。
- 保留最近15份本目录归属明确的已验证备份，验证/恢复/传输持统一锁；测试他人文件和软链接不会被清理。

## 4. 异机保存和失败告警

- SSH命令、上传、远端创建、下载或回读任一步失败均不能记录异机成功；先写外部边界失败回归，再实现薄入口。
- 密钥和数据库凭证只传远端路径；复制密文及认证清单，独立备份机验证完成后更新已验证副本状态。
- 实际HTTP测试接收器接收失败事件；缺配置与投递失败明确区分，敏感错误不写公开告警。
- 替换PowerShell旧流程并提供systemd service/timer例子，检查退出码、重复执行锁和中断恢复说明。

## 5. 量化演练与CI

- backup:validate使用独立源/目标，生成可见与不可见marker、角色和向量数据；记录源时间、已确认提交、模拟故障、最后恢复marker和误差。
- 报告观测RPO及保守覆盖界限、数据库RTO、数据量、下载/拉镜像是否计入；源端与异机验证时间分别记录。
- 接入CI真实Docker演练，JSON证据保存身份/阶段/结果，密钥、凭证和原始用户数据不上传。
- 独立智能体验证真实恢复、隔离和失败路径；发现问题先复现再修复。

## 6. 交付

- 同步备份操作说明、验证记录、CODE_WIKI、coverage-matrix、CHANGELOG、docs/memory与changeset。
- 完整qa:gate、源码smoke及真实恢复演练通过，核对最终候选CI及原始证据后直接合并。
- 回写Manager实际需求状态与交付进度，记录未配置的生产备份机、凭证和告警；不把本地测试当作生产异机保障。
