# P04恢复部署交接实施计划

设计依据：`docs/superpowers/specs/2026-09-12-restored-deployment-design.md`。用户已授权按需求持续实现、独立验收、CI通过后合并。此计划在备份/传输阶段之后执行，尚未完成的事项不计入P04交付。

执行状态：配置/来源、独占归属、12连接和部署/回退及SSH回执已实现；正式11项实机、故障/外联隔离、资源清理、独立18项回读及最新qa/smoke均通过。剩余交付步骤为提交后的精确候选CI核验与合并。操作与证据见docs/features/restored-deployment.md和docs/validation/2026-09-12-restored-deployment.md。

## 1. 配置与来源契约

- RED：现有v1配置固定configVersion与渲染保持一致，v2缺字段/错误ID/错误模式被拒绝。
- 新增恢复绑定schema，保持v1 canonical序列化不变；v2明确嵌入资源和来源身份。
- `backup:handoff`读取`--backup`、`--key-file`、`--restore-receipt`、既有`--config`与全新`--output`，完成真实资源/目录校验后写v2配置；不覆盖已有输出。
- 保留秘密路径隔离、认证备份清单和恢复成功回执匹配，不从用户手写operation标签推导已恢复事实。

## 2. 独占归属与连接绑定

- RED：两个不同state-dir竞争同一恢复实例，只能一个领取；已有他人容器、网络或卷拒绝；同名替换容器拒绝。
- 集中实现不可变资源身份、独占归属、网络成员检查与主库可用性，不修改恢复卷或重启恢复PG。
- RED：八条主连接、四条跨库连接中的任意遗漏/错误库名/连接参数覆盖不能访问原库。
- 解析私有env并在子进程环境改写目标，保持env文件字节和公开Compose无秘密。构建可测试的连接字段清单，避免遗漏上游引用。

## 3. 部署与回退

- v2渲染17应用及内部项目网络，后端加入恢复网络；只有网关另加有明确归属和角色标签的ingress网络供宿主访问。移除自建postgres/初始化挂载/相关健康依赖，拒绝业务进程进入ingress或任意外部网络。
- 部署前后核验实际恢复DB与17应用readiness；状态目录绑定恢复身份，后续升级或回退不能换库。
- 旧v1继续18容器契约；旧bundle/configVersion与失败/回退行为均跑回归。
- 新回执保留数据库绑定、备份/恢复ID和外部隔离事实；SSH部署上传新依赖并核对回读绑定。

## 4. 真实隔离验收

- 独立源与恢复实例写八库唯一标记，准备能经业务API确认的测试记录；使用已有经过验证的固定制品A/B。
- 全新项目和state-dir部署17服务，证明应用读取恢复数据，主连接与四上游连接均不落到原库；记录源容器ID、卷、env摘要和marker保持。
- 故意坏凭证、拉取失败、迁移失败、目标身份替换和归属竞争，确认成功指针不错误推进、源数据不受影响。
- 应用A到B到A回退保持恢复实例不重建，明确数据库迁移不逆向；最终只清理本轮所有权匹配的测试资源。
- 禁止恢复任务在验收时访问真实外部服务；未配置的生产集成和切流独立记录。
