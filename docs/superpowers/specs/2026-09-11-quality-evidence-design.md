# P01/P02：数据库验证与提交证据

用户已授权依据既有 26 条规划持续实施，完成独立验收及 CI 后直接合并。PR #69/#70 已先后合入 main，本批补齐 P01 的可核验报告与 P02 的关键数据库验证。使用单任务 worktree；设计中的常规取舍由本次授权执行，不等待逐项确认。

## 现有问题

统一 qa:gate 和 Manager 强制集成入口已经落地，但其余 26 个文件会将数据库连接、迁移或应用装配异常转为 skip。默认 Turbo strict 模式没有声明数据库和测试模式环境，数据库测试还能复用缓存。部分测试硬编码业务库或 5432，跨包清场可能互相干扰。PR 的两个复选框不能证明实际候选已经测试。

## 取舍与边界

采用“纯单测保留缓存，数据库套件独立强制执行”的方案。仅给所有测试关闭缓存不能解决隔离和错误吞没；只提供数据库服务也不能证明测试执行。保留已有行为用例，统一配置、初始化、结果收集和失败策略，不重写业务实现。

这批验证真实 PostgreSQL 查询和迁移，外部模型/接口使用测试桩或 mock；报告明确标识这两个维度。真实问答效果评测属于 P16，不以向量桩、HTTP 健康或普通单测替代。

## 执行链路

1. 维护受版本控制的关键套件清单：项目、文件、最低执行数。文件丢失、清单遗漏或报告没有执行对应文件，门禁失败。
2. 关键数据库用例从普通 Vitest test 配置中排除，由独立 test:db 启动器直接运行，不经过 Turbo 测试缓存。Manager 原有单项目命令保持兼容。
3. 显式配置测试 PostgreSQL 连接；统一验证专用库名、版本与所需扩展。每次运行生成独立命名空间，每个项目的主库和上游库也分开，禁止把原业务库作为测试目标。
4. 在导入测试模块前创建本次所需数据库并执行迁移；自举测试另分配未创建的临时库。硬编码连接改用本次环境。连接、迁移或应用装配异常保留原错误并失败，不能变成通过。
5. Vitest 输出每项目独立 JSON。汇总核对全部关键文件、最低执行数、失败/skip/todo；数据库模式要求 skip=0。缺文件、零测试、陈旧报告同样失败。
6. qa:gate 记录 lint、build/普通单测、coverage、infra、docs、design 与数据库阶段结果。即使失败也写报告，保留失败阶段，禁止生成成功回执。
7. 报告包含 PR head、实际 checkout、base、工作树指纹、运行模式、run/attempt、时间与各阶段结果。CI PR 默认 checkout 为合并提交，两个 SHA 分开记录。报告不能包含数据库密码或模型/平台密钥。
8. CI 上传与候选及运行编号绑定的验证产物；保留原复选框作为说明，实际结果由运行产物与 required checks 确定。

## 可执行验收

| 行为 | 预期 |
|---|---|
| 数据库地址错误、缺扩展、迁移或应用装配失败 | 非零退出并保留原始原因 |
| 有效连接指向业务库 | 连接前拒绝，禁止清场 |
| 关键报告含 skip/todo、缺文件或零测试 | 汇总失败 |
| 先成功，再使数据库不可用 | 再次执行必须失败，不能命中旧成功缓存 |
| 两次运行或两个项目并行 | 数据库命名空间不同，上游清场不会相互影响 |
| 提交/工作树/运行标识变化后复用报告 | 拒绝旧证据 |
| 新旧测试命令 | 普通 test 运行单元测试；qa:gate 和 test:db 强制真实数据库验证 |
| 桩模式报告 | 明确 DB=real、external=stub/mock；live-model 未执行 |
| Designer 既有生成交互定位守卫 | 对照真实输入框实现改为等待和失败断言，不再空转跳过 |

## 实施顺序与验证

先对数据库目标校验和报告判定写行为测试，再实现最小通过路径；随后接一个真实数据库套件，逐项目迁移其余关键套件；最后集成 qa:gate/CI 和文档。每个行为按 RED→GREEN 推进。

独立测试智能体需额外验证错误连接、缺扩展、跳过/旧报告注入、隔离与缓存失效。使用本轮独立 pgvector PostgreSQL 容器（127.0.0.1:55433），不操作原 5432。完整门禁、冒烟及相关 E2E 通过后创建 PR，CI 成功后自动合入 main，并更新规划账本。

正式使用文档、CODE_WIKI、coverage-matrix、CHANGELOG、docs/memory 与 changeset 随实现同步。运行日志和报告为运行时产物，不提交 Git。
